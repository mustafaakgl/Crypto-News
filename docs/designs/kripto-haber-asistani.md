# Design: Kripto Haber Asistanı (günlük doğrulanmış piyasa brifingi)

## Problem Statement

Her sabah onlarca kripto haber sitesini, borsa duyurusunu ve analist yayınını tek tek okumak zaman alıyor ve önemli gelişmeler kaçıyor. İstenen: her gün 08:00 Europe/Berlin'de Telegram'a gelen, Türkçe, kaynak bağlantılı, doğrulanmış bilgiyi analist görüşünden ve söylentiden açıkça ayıran tek bir rapor. Amaç işlem kararları için düzenli ve doğrulanabilir bilgi akışı; kesin fiyat tahmini yok, olası piyasa etkisi yorum olarak.

Kullanıcının sözleriyle: "tabi burada haber alınacak kaynaklar çok önemli" ve "hiçbir şey ödemek istemiyorum".

## What Makes This Cool

Mevcut 13 açık kaynak digest botunun hiçbiri "doğrulanmış / görüş / söylenti" ayrımı yapmıyor; hepsi haber başlığından LLM'e özet yazdırıyor. Buradaki fark: **doğrulama bir LLM işi değil, bir join işi.** Bir haber kümesi Binance/Upbit duyuru JSON'u, SEC EDGAR dosyası, GitHub release veya regülatör RSS'iyle eşleşiyorsa "doğrulandı"; yalnızca haber sitelerinde geçiyorsa "haber (resmî teyit yok)"; yalnızca analist kaynağındaysa "görüş". Deterministik, ücretsiz, test edilebilir. LLM yalnızca Türkçe metni yazar ve **URL üretmez**: yazar yalnızca `item_id` referansları verir, bağlantıları deterministik adım `digest.json`'dan enjekte eder. Uydurma link yapısal olarak imkânsız.

## Constraints

- **Sıfır veri bütçesi.** Ücretli unlock API'si yok (DefiLlama emissions 402, Tokenomist $250/ay, CryptoRank Pro), X/Twitter API yok (pay-per-use, ~$40-80/ay). Ücretsiz aggregator'lar öldü: CryptoPanic RSS 410, CoinGecko news Pro-only.
- **Makine:** Apple M2, 8 GB RAM. 7B q4 yerel model 6-10k token girdide dakikalar sürer ve Türkçe kalitesi sınırlı → Ollama yalnızca yedek sağlayıcı; birincil sağlayıcı kullanıcının mevcut anahtarı (Açık soru 1, kodlamadan önce çözülür).
- **LLM:** Kullanıcı "kendi LLM'im Ordivan var" dedi. Fleet reposundaki `backend/src/ordivan/ordivan.config.ts` yorumu: "local — Gerçek Ordivan. Bu fazda kullanılmıyor". Ordivan bugün sağlayıcı olarak hazır değil. CLI, OpenAI-uyumlu HTTP arayüzü (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`) üzerinden konuşur; Anthropic, OpenAI, OpenRouter, Ollama ve ileride Ordivan tek env değişikliğiyle takılır.
- **Teslimat:** Telegram, 08:00 Europe/Berlin, Türkçe. OpenClaw broadcast-channel desteği belgelenmemiş (issue #17850) → özel supergroup veya forum topic.
- **Çalışma yeri (karar):** Kullanıcının Mac'i. `sudo pmset repeat wakeorpoweron MTWRFSU 07:55:00` + automation'ı `caffeinate -i` ile sarmak. Ön koşul: Mac prize takılı ve kapak açık ya da harici ekrana bağlı (kapalı kapak + pil ile zamanlanmış uyanma çalışmaz). Bu ön koşul sağlanamıyorsa Oracle Free ARM VPS öne çekilir (YouTube transkriptleri datacenter IP'den engellenir; faz 2'de zaten).
- **OpenClaw gerçekleri (docs.openclaw.ai, 2026-09-15):** RSS'i yerel parse etmez → script gerekli. Automations: `--command` (LLM'siz shell job) `--announce --channel telegram --to "-100…"` ile çıktıyı teslim edebilir; `--tz Europe/Berlin --exact`; failure alert 2 ardışık hatadan sonra. `openclaw message send --channel telegram --target <id>` belgelenmiş. Isolated-session + announce teslimat bug'ı (#29660) geçmişte yaşandı → bu tasarım isolated ajan turu kullanmaz; tek `--command` job.
- **Güvenlik:** OpenClaw rehberi okunan web içeriğini düşman sayar. Bu tasarımda **okuyucu ajan yok**: tüm fetch işi LLM dışındaki CLI'da; LLM'e yalnızca normalize edilmiş, uzunluğu kırpılmış başlık/özet metinleri gider, araç erişimi yok (düz HTTP çağrısı). ClawHub "crypto" skill'leri 2026 malware dalgasının hedefiydi (341+ zararlı skill) → hazır skill kurulmaz.
- **Tier-0 borsa uç noktaları resmî ama belgesiz** (Binance `bapi/composite`, Upbit `api-manager`, Bithumb v1, OKX support). Habersiz değişebilir, UA/geo engeli olabilir → her kaynakta `enabled` bayrağı, sağlık sayacı (3 ardışık hata → otomatik devre dışı + tek seferlik not), Binance için `t.me/s/binance_announcements` yedek. Lansmanda Bithumb, SlowMist ve OKX `enabled:false`; ilk hafta sonunda açılır (v1'de 6 özel parser var, kademeli devreye alma).

## Premises (kabul edildi)

1. Kaynak katmanı RSS/JSON öncelikli; X/Twitter ilk sürümde yok. Analistler feed'i olanlardan seçilir.
2. "Doğrulandı" = Tier-0 resmî yapısal kaynakla eşleşme (join). LLM URL üretmez; bağlantılar `item_id` üzerinden enjekte edilir.
3. Toplama/dedup/kümeleme/doğrulama/sıralama deterministik; LLM yalnızca Türkçe yazım. Okuyucu ajan yok.
4. Unlock takvimi: elle tutulan `config/unlocks.yaml` (≥$50M unlock'lar, haftalık güncellenir; Tokenomist web'den okunur). Ücretli API yok.
5. Telegram özel supergroup/topic'e teslimat.
6. Coin, kaynak ve eşikler `config/*.yaml`; başlangıçta zod şemasıyla doğrulanır (`npm run config:check`); kod değişmeden düzenlenir.

Ek sınır (D5/D6): hiçbir ücretli servis yok; LLM sağlayıcısı kullanıcının mevcut anahtarı/aboneliği, yedek Ollama.

## Approaches Considered

- **A) OpenClaw-native skill (minimal):** tek SKILL.md, kümeleme ve doğrulama LLM'de. Reddedildi: prior-art'ın bilinen hata modları (uydurma link, tekrar eden haber), test edilemez, geniş injection yüzeyi.
- **C) Ordivan job tipi (Fleet içinde):** Reddedildi (şimdilik): Ordivan local modu yok, connector protokolü web araçlarını yasaklıyor (FORBIDDEN_TOOLS), Telegram+cron sıfırdan, Fleet'in tenant/migration kuralları kişisel bot için yük.
- **B) Deterministik pipeline CLI + OpenClaw ince orkestratör:** SEÇİLDİ. İnceleme sonrası revizyon: iki aşamalı cron (07:40 build + 08:00 isolated ajan) yerine **tek süreçli çalıştırma**; OpenClaw v1'de yalnızca cron ve Telegram bot kimliği sağlar. (Faz 2: OpenClaw sohbetinden "3. maddeyi aç" gibi Q&A, `out/digest-*.json` dosyalarını okuyan bir skill ile.)

## Recommended Approach (B, tek süreç)

### Bileşenler

```

│   ├── assets.yaml        # varlıklar, aliases, exclude_patterns, newsworthy kuralları
```

### Günlük akış (tek OpenClaw automation)

```
openclaw automations create "0 8 * * *" --tz Europe/Berlin --exact \
  --name "Kripto brifingi" \
  --command "caffeinate -i npm run digest:run" --command-cwd "/Users/mustafaakgul/kripto-asistan" \
  --announce --channel telegram --to "<supergroup-id>"
```

`digest:run` adımları (tek süreç, tek hata alanı):

1. **Pencere:** `[last-run.json.finishedAt − 6 saat, now]`; ilk çalıştırma ve kaçırılan günler için otomatik telafi. Üst sınır 72 saat. Önce `state/pending-digest.json` kontrol edilir: önceki koşudan gönderilmemiş parça varsa ve 20 saatten yeniyse önce o parçalar gönderilir, sonra normal akış devam eder (günün raporu her koşulda üretilir); 20 saatten eskiyse atılır ve rapora "⏭ Dünkü gönderilemeyen parçalar atlandı" notu düşer.
2. **Fetch:** eşzamanlılık 8, kaynak başına 15 s timeout, 1 tekrar, hata durumunda devam; **global fetch süresi 4 dk**, süre dolunca gelenle devam. Hatalar `sourceErrors[]`'a yazılır ve `source-health.json` sayacı artar. Uyarı sözleşmesi tek yerde: rapor altbilgisi bu koşuda alınamayan kaynakları her zaman listeler; Tier-0'ın >%25'i hatalıysa rapor başına "⚠️ Resmî kaynakların bir kısmı alınamadı; doğrulama eksik olabilir" bandı; 3 ardışık hata → kaynak `enabled:false` yapılır ve bir kez "🔌 <kaynak> devre dışı bırakıldı" notu düşer.
3. **Normalize:** Item `{id, sourceId, tier, kind, exchange?, title, url, canonicalUrl, publishedAt(UTC), dateInferred, fetchedAt, assets[], entities[], text≤600}`. `kind ∈ {listing, delisting, release, hack, filing, press, status, post, other}` kaynağa göre `sources.yaml`'da atanır (Upbit/Bithumb/Kraken için ek regex); kümenin kind'ı Tier-0 üyesinin kind'ıdır. Tarihsiz öğelerde (ESMA, bazı scrape'ler) `publishedAt = fetchedAt`, `dateInferred:true`; bunlar zaman penceresi kontrolünden muaf tutulur, ancak `seen.json.seenUrls` (canonicalUrl → firstSeenAt, 30 gün TTL) içinde varsa düşürülür. Coinbase products diff: ilk koşu yalnızca snapshot yazar, öğe üretmez. Varlık eşleme: `assets.yaml.aliases` ile kelime sınırında; ≤4 karakterli ticker'lar büyük/küçük harf duyarlı; `exclude_patterns` (ör. "hyperlink", "solar") düşer. Entity eşleme: `filters.yaml.entities` (Tether, Circle, Coinbase, Grayscale, BlackRock, SEC, Fed …). Başlık normalizasyonu: küçük harf, noktalama ve stopword temizliği, hafif stemming → `titleTokens`.
4. **Dedup (öğe düzeyi):** `canonicalUrl` eşitliği veya `titleTokens` simhash Hamming ≤ 3 → aynı öğe, tek kayıt.
5. **Cluster:** aynı olay = 36 saat penceresi içinde varlık/entity çakışması VE metin benzerliği. Çakışma: `assets ∩ ≠ ∅`, ya da her iki tarafta `assets` boşsa `entities ∩ ≥ 1`, ya da `entities ∩ ≥ 2`. Benzerlik: `titleTokens` Jaccard ≥ `filters.yaml.clusterJaccard` (başlangıç 0.38, fixture testleriyle ayarlanır) VEYA aynı canonical URL'ye link. Kümeleme tek bağlantılı (single-linkage): öğe, kümenin herhangi bir üyesiyle eşleşiyorsa katılır. **Küme belleği:** `seen.json`, raporlanmış küme parmak izlerini 72 saat tutar: `{clusterId, assets, entities, memberTitleTokens: string[][], canonicalUrls[], label, reportedAt}` ve ayrıca `seenUrls` (30 gün). Bellek eşleşmesi 36 saatlik pencereden muaftır: yeni küme, çakışma kuralı sağlanıyorsa VE (herhangi bir üye başlığıyla Jaccard ≥ eşik VEYA herhangi bir canonicalUrl eşit) ise eşleşir. Eşleşen küme yeni Tier-0 öğe içeriyorsa `update:true` ile yeniden çıkar, içermiyorsa bastırılır.
6. **Verify:** kümede Tier-0 öğe var → `verified ✅`; yalnızca Tier-1, ≥2 outlet → `news_multi 📰`; yalnızca Tier-1, 1 outlet → `news_single 📰¹`; yalnızca Tier-2 → `opinion 💬`. Forum/mailing-list öğeleri Tier-2 sayılır (tartışma, resmî değil). Cointelegraph `countsForMulti:false`: yalnızca Cointelegraph'tan oluşan küme **düşürülür**; Cointelegraph + 1 başka outlet = `news_single`.
7. **Rank:** `score = 3·[verified] + 2·[filters.yaml tetiklendi] + 1·[izlenen varlık] + 1·[küratörlü Tier-2 kaynak, forum hariç] + 1·log2(kaynak sayısı)`. Borsa listing/delisting kümeleri: varlık `assets.yaml`'da ise normal puanlanır; değilse ve borsa ∈ {Binance, Coinbase, Upbit} ise +2 filtre bonusu uygulanmaz ve bu kümeler tek bir toplu maddede birleştirilir ("Borsa listeleme/çıkarma: X (Binance), Y (Upbit) …", sabit skor 2, sayılmaz 12 sınırında ayrı yer tutar); diğer borsalar düşer. Eşitlikte Tier-0 kaynak sayısı, sonra `publishedAt` desc. Kesme: `score ≥ 2`, en fazla 12 madde. **Boş gün kuralı:** eşiği geçen <3 madde varsa eşik 1'e düşer; yine yoksa rapor yalnızca bağlam satırı + takvim + "Bugün eşiği geçen gelişme yok" ile gönderilir. Rapor hiçbir gün boş kalmaz.
8. **Write:** `out/digest-YYYY-MM-DD.json` yazılır. LLM'e giden girdi: `context`, `calendar`, `items[]` (id, label, title, text, sourceNames, assets, publishedAt). Sistem talimatı Türkçe; her madde için Ne oldu / Neden önemli / Hangi varlıklar / Ne takip edilmeli; olası piyasa etkisi yorum, fiyat tahmini yasak. **Çıktı sözleşmesi (JSON):** `{items:[{id, baslik, ne_oldu, neden_onemli, varliklar, takip}], piyasa_notu}` — URL alanı yok. Doğrulama: her `id` girdide var, girdideki her `verified` id çıktıda var, alan uzunluk sınırları. Eksik `verified` id → tüm rapor için iskelet; eksik diğer id → yalnızca o madde iskelet. **Sağlayıcı zinciri:** birincil (`LLM_BASE_URL`, 90 s timeout) → 1 tekrar (aktarım hatası VE geçersiz JSON için) → yalnızca `LLM_FALLBACK_BASE_URL` tanımlıysa ve geçen süre < 5 dk ise Ollama (2 dk timeout) → iskelet fallback. Ollama tanımlı değilse doğrudan iskelet.
9. **Render:** her madde için `✅/📰/📰¹/💬` etiketi, `digest.json`'dan kaynak adı + URL + yayın zamanı (Berlin) enjekte edilir. Telegram HTML alt kümesi: `b i u s a code pre blockquote`; `< > &` kaçışlanır. **Parçalama deterministik:** madde sınırında, her parça ≤ 3900 karakter, açık tag parçada kapanır. Parçalar `state/pending-digest.json`'a `{chunkIndex, html, sent:false}` olarak yazılır. İskelet fallback (LLM hatası/geçersiz çıktı): aynı render, `ne_oldu` yerine kaynak başlığı (İngilizce) + Türkçe iskelet; rapor başına "🤖 Özet üretilemedi, ham başlıklar" notu.
10. **Send:** birincil gönderici Telegram Bot API `sendMessage` (`parse_mode=HTML`, `disable_web_page_preview=true`), aynı bot token'ı OpenClaw ile paylaşır; yedek `openclaw message send --channel telegram --target <id>` (yalnızca HTML parse_mode geçirdiği Next Step 1 testinde doğrulanırsa). Her başarılı parça `pending-digest.json`'da `sent:true`. Tüm parçalar gönderildikten sonra `seen.json` (küme parmak izleri + seenUrls) ve `last-run.json` yazılır, `pending-digest.json` silinir (teslimat öncesi asla). Herhangi bir aşamada yakalanmamış hata: CLI kendi catch-all'ında Bot API ile "❌ Brifing üretilemedi: <kısa neden>" gönderir, durum satırını yalnızca stderr'e yazar (çift hata mesajı olmaz) ve ≠0 çıkar → OpenClaw failure alert (2 ardışık hata sonrası) ek güvence.

**Env değişkenleri:** `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_FALLBACK_BASE_URL?`, `LLM_FALLBACK_MODEL?`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `CONTACT_EMAIL` (SEC/BLS bot UA için), `TZ=Europe/Berlin`. `.env` git dışı, 0600.

**Fetcher yapısı:** `json-api` fetcher'ı kaynak başına `sources.yaml`'daki yol eşlemesiyle (`items`, `title`, `url`, `date` JSONPath + opsiyonel regex) çalışır; böylece ~15 JSON şekli config'dir. Gerçek özel adaptörler: Coinbase products diff, EDGAR full-text, `t.me/s` HTML, SlowMist HTML, BLS iCal (5 adet).

**stdout sözleşmesi:** CLI stdout'a yalnızca tek satır durum yazar ("✅ Brifing gönderildi, 9 madde, 2 parça" / "❌ hata: …"); tüm log stderr ve `logs/`'a gider. Böylece `--announce` OpenClaw'ın hangi davranışı olursa olsun (son satır ya da tüm stdout) yalnızca durum satırını iletir; içerik `message send` ile gider.

### digest.json şeması (özet)

```ts
type Digest = {
  generatedAt: string; windowFrom: string; windowTo: string; tz: "Europe/Berlin";
  context: { btcUsd, btcChg24h, ethUsd, ethChg24h, fearGreed, btcEtfNetFlowUsd?, btcEtfFlowDate?, stableSupplyDelta7dPct? /* state/stablecoin-supply.json günlük snapshot'larından (≥8 gün) hesaplanır */ };
  calendar: { at: string; tz: string; title: string; kind: "macro"|"unlock"|"fork"|"etf"; asset?: string; url?: string }[];
  items: { id: string; label: "verified"|"news_multi"|"news_single"|"opinion"; score: number; title: string; text: string;
           assets: string[]; entities: string[]; publishedAt: string;
           sources: { sourceId: string; name: string; tier: 0|1|2; url: string; publishedAt: string }[];
           update?: boolean }[];
  sourceErrors: { sourceId: string; error: string }[];
};
```
