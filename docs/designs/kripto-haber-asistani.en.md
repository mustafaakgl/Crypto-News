# Design: Crypto News Assistant (daily verified market briefing)

Generated by /office-hours on 2026-09-15
Branch: main
Repo: kripto-asistan (local, no remote yet)
Status: APPROVED
Mode: Builder
Language: English translation of `kripto-haber-asistani.md` (Turkish original is authoritative)

## Problem Statement

Reading dozens of crypto news sites, exchange announcements and analyst publications one by one every morning takes time, and important developments slip through. Wanted: a single report delivered to Telegram every day at 08:00 Europe/Berlin, in Turkish, with source links, that clearly separates verified information from analyst opinion and rumor. Goal: a regular, verifiable information flow for trading decisions; no definite price predictions, possible market impact only as commentary.

In the user's words: "of course the sources the news is taken from are very important here" and "I don't want to pay for anything".

## What Makes This Cool

None of the 13 existing open-source digest bots separates "verified / opinion / rumor"; all of them have an LLM summarize from headlines. The difference here: **verification is not an LLM task, it is a join.** If a news cluster matches a Binance/Upbit announcement JSON, an SEC EDGAR filing, a GitHub release or a regulator RSS item, it is "verified"; if it appears only on news sites, it is "news (no official confirmation)"; if it comes only from an analyst source, it is "opinion". Deterministic, free, testable. The LLM only writes the Turkish text and **never produces URLs**: the writer returns only `item_id` references, and a deterministic step injects the links from `digest.json`. A fabricated link is structurally impossible.

## Constraints

- **Zero data budget.** No paid unlock API (DefiLlama emissions 402, Tokenomist $250/mo, CryptoRank Pro), no X/Twitter API (pay-per-use, ~$40-80/mo). Free aggregators are dead: CryptoPanic RSS 410, CoinGecko news Pro-only.
- **Machine:** Apple M2, 8 GB RAM. A 7B q4 local model takes minutes on 6-10k token input and its Turkish quality is limited → Ollama is a fallback provider only; the primary provider is the user's existing key (Open Question 1, resolved before coding).
- **LLM:** The user said "I have my own LLM, Ordivan". The comment in the Fleet repo's `backend/src/ordivan/ordivan.config.ts` reads: "local — Real Ordivan. Not used in this phase". Ordivan is not ready as a provider today. The CLI talks over an OpenAI-compatible HTTP interface (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`); Anthropic, OpenAI, OpenRouter, Ollama and later Ordivan plug in with a single env change.
- **Delivery:** Telegram, 08:00 Europe/Berlin, Turkish. OpenClaw broadcast-channel support is undocumented (issue #17850) → private supergroup or forum topic.
- **Where it runs (decision):** The user's Mac. `sudo pmset repeat wakeorpoweron MTWRFSU 07:55:00` + wrap the automation in `caffeinate -i`. Precondition: Mac plugged in and lid open, or attached to an external display (scheduled wake does not work with closed lid on battery). If this precondition cannot be met, the Oracle Free ARM VPS moves up (YouTube transcripts are blocked from datacenter IPs; phase 2 anyway).
- **OpenClaw facts (docs.openclaw.ai, 2026-09-15):** does not parse RSS natively → script required. Automations: `--command` (LLM-free shell job) can deliver output with `--announce --channel telegram --to "-100…"`; `--tz Europe/Berlin --exact`; failure alert after 2 consecutive failures. `openclaw message send --channel telegram --target <id>` is documented. An isolated-session + announce delivery bug (#29660) occurred in the past → this design uses no isolated agent turn; a single `--command` job.
- **Security:** The OpenClaw guide treats fetched web content as hostile. In this design there is **no reader agent**: all fetching happens in the CLI outside the LLM; the LLM receives only normalized, length-trimmed title/summary text and has no tool access (plain HTTP call). ClawHub "crypto" skills were the target of the 2026 malware wave (341+ malicious skills) → no ready-made skills are installed.
- **Tier-0 exchange endpoints are official but undocumented** (Binance `bapi/composite`, Upbit `api-manager`, Bithumb v1, OKX support). They can change without notice and may have UA/geo blocks → `enabled` flag per source, health counter (3 consecutive failures → auto-disable + one-time note), `t.me/s/binance_announcements` as Binance backup. At launch Bithumb, SlowMist and OKX are `enabled:false`; switched on at the end of week one (v1 has 6 bespoke parsers, staged rollout).

## Premises (accepted)

1. Source layer is RSS/JSON first; no X/Twitter in the first version. Analysts are chosen from those with feeds.
2. "Verified" = match (join) with a Tier-0 official structured source. The LLM produces no URLs; links are injected via `item_id`.
3. Collection/dedup/clustering/verification/ranking are deterministic; the LLM only writes Turkish. No reader agent.
4. Unlock calendar: hand-maintained `config/unlocks.yaml` (unlocks ≥ $50M, updated weekly; read from the Tokenomist website). No paid API.
5. Delivery to a private Telegram supergroup/topic.
6. Coins, sources and thresholds live in `config/*.yaml`; validated at startup with a zod schema (`npm run config:check`); editable without code changes.

Additional limit (D5/D6): no paid service at all; LLM provider is the user's existing key/subscription, Ollama as fallback.

## Approaches Considered

- **A) OpenClaw-native skill (minimal):** single SKILL.md, clustering and verification in the LLM. Rejected: known failure modes of prior art (fabricated links, repeated stories), untestable, wide injection surface.
- **C) Ordivan job type (inside Fleet):** Rejected (for now): Ordivan local mode does not exist, the connector protocol forbids web tools (FORBIDDEN_TOOLS), Telegram+cron from scratch, Fleet's tenant/migration rules are a burden for a personal bot.
- **B) Deterministic pipeline CLI + OpenClaw thin orchestrator:** CHOSEN. Post-review revision: instead of a two-step cron (07:40 build + 08:00 isolated agent), **single-process run**; in v1 OpenClaw provides only cron and the Telegram bot identity. (Phase 2: Q&A from OpenClaw chat such as "open item 3", via a skill that reads `out/digest-*.json`.)

## Recommended Approach (B, single process)

### Daily flow (single OpenClaw automation)

```
openclaw automations create "0 8 * * *" --tz Europe/Berlin --exact \
  --name "Kripto brifingi" \
  --command "caffeinate -i npm run digest:run" --command-cwd "/Users/mustafaakgul/kripto-asistan" \
  --announce --channel telegram --to "<supergroup-id>"
```

`digest:run` steps (single process, single failure domain):

1. **Window:** `[last-run.json.finishedAt − 6 hours, now]`; automatic catch-up for the first run and missed days. Upper bound 72 hours. `state/pending-digest.json` is checked first: if unsent chunks from the previous run exist and are newer than 20 hours, they are sent first and the normal flow continues (the day's report is always produced); if older than 20 hours they are discarded and the report gets a "⏭ Yesterday's unsent chunks were skipped" note.
2. **Fetch:** concurrency 8, 15 s timeout per source, 1 retry, continue on error; **global fetch budget 4 min**, proceed with whatever arrived when it expires. Errors go to `sourceErrors[]` and increment the `source-health.json` counter. Warning contract in one place: the report footer always lists sources that failed in this run; if >25% of Tier-0 failed, a banner "⚠️ Some official sources could not be fetched; verification may be incomplete" at the top; 3 consecutive failures → source set to `enabled:false` with a one-time "🔌 <source> disabled" note.
3. **Normalize:** Item `{id, sourceId, tier, kind, exchange?, title, url, canonicalUrl, publishedAt(UTC), dateInferred, fetchedAt, assets[], entities[], text≤600}`. `kind ∈ {listing, delisting, release, hack, filing, press, status, post, other}` is assigned per source in `sources.yaml` (extra regex for Upbit/Bithumb/Kraken); a cluster's kind is the kind of its Tier-0 member. Dateless items (ESMA, some scrapes): `publishedAt = fetchedAt`, `dateInferred:true`; exempt from the time-window check but dropped if present in `seen.json.seenUrls` (canonicalUrl → firstSeenAt, 30-day TTL). Coinbase products diff: the first run only writes the snapshot and emits nothing. Asset matching: `assets.yaml.aliases` on word boundaries; tickers ≤4 chars are case-sensitive; `exclude_patterns` (e.g. "hyperlink", "solar") drop. Entity matching: `filters.yaml.entities` (Tether, Circle, Coinbase, Grayscale, BlackRock, SEC, Fed …). Title normalization: lowercase, strip punctuation and stopwords, light stemming → `titleTokens`.
4. **Dedup (item level):** `canonicalUrl` equality or `titleTokens` simhash Hamming ≤ 3 → same item, single record.
5. **Cluster:** same event = asset/entity overlap AND text similarity within a 36-hour window. Overlap: `assets ∩ ≠ ∅`, or if `assets` is empty on both sides `entities ∩ ≥ 1`, or `entities ∩ ≥ 2`. Similarity: `titleTokens` Jaccard ≥ `filters.yaml.clusterJaccard` (initial 0.38, tuned by fixture tests) OR link to the same canonical URL. Single-linkage clustering: an item joins if it matches any member. **Cluster memory:** `seen.json` keeps fingerprints of reported clusters for 72 hours: `{clusterId, assets, entities, memberTitleTokens: string[][], canonicalUrls[], label, reportedAt}` plus `seenUrls` (30 days). Memory matching is exempt from the 36-hour window: a new cluster matches if the overlap rule holds AND (Jaccard ≥ threshold against any member title OR any canonicalUrl equal). A matched cluster re-emits with `update:true` if it contains a new Tier-0 item, otherwise it is suppressed.
6. **Verify:** Tier-0 item in cluster → `verified ✅`; only Tier-1, ≥2 outlets → `news_multi 📰`; only Tier-1, 1 outlet → `news_single 📰¹`; only Tier-2 → `opinion 💬`. Forum/mailing-list items count as Tier-2 (discussion, not official). Cointelegraph `countsForMulti:false`: a cluster consisting only of Cointelegraph is **dropped**; Cointelegraph + 1 other outlet = `news_single`.
7. **Rank:** `score = 3·[verified] + 2·[filters.yaml triggered] + 1·[tracked asset] + 1·[curated Tier-2 source, forums excluded] + 1·log2(source count)`. Exchange listing/delisting clusters: scored normally if the asset is in `assets.yaml`; otherwise, if exchange ∈ {Binance, Coinbase, Upbit}, the +2 filter bonus is not applied and these clusters are merged into one aggregated item ("Exchange listings/delistings: X (Binance), Y (Upbit) …", fixed score 2, holds one slot outside the 12 limit); other exchanges drop. Ties: Tier-0 source count, then `publishedAt` desc. Cutoff: `score ≥ 2`, at most 12 items. **Empty-day rule:** if <3 items pass, the threshold drops to 1; if still none, the report is sent with only the context line + calendar + "No development passed the threshold today". The report is never empty.
8. **Write:** `out/digest-YYYY-MM-DD.json` is written. LLM input: `context`, `calendar`, `items[]` (id, label, title, text, sourceNames, assets, publishedAt). System instruction in Turkish; per item What happened / Why it matters / Which assets / What to watch; possible market impact as commentary, price predictions forbidden. **Output contract (JSON):** `{items:[{id, baslik, ne_oldu, neden_onemli, varliklar, takip}], piyasa_notu}` — no URL field. Validation: every `id` exists in the input, every `verified` input id appears in the output, field length limits. Missing `verified` id → skeleton for the whole report; missing other id → skeleton for that item only. **Provider chain:** primary (`LLM_BASE_URL`, 90 s timeout) → 1 retry (for transport errors AND invalid JSON) → Ollama only if `LLM_FALLBACK_BASE_URL` is set and elapsed time < 5 min (2 min timeout) → skeleton fallback. If Ollama is not configured, straight to skeleton.
9. **Render:** `✅/📰/📰¹/💬` label per item; source name + URL + publish time (Berlin) injected from `digest.json`. Telegram HTML subset: `b i u s a code pre blockquote`; `< > &` escaped. **Deterministic chunking:** at item boundaries, each chunk ≤ 3900 chars, open tags closed within the chunk. Chunks are written to `state/pending-digest.json` as `{chunkIndex, html, sent:false}`. Skeleton fallback (LLM error/invalid output): same render, source title (English) instead of `ne_oldu` + Turkish scaffold; a "🤖 Summary could not be generated, raw headlines" note at the top.
10. **Send:** primary sender is Telegram Bot API `sendMessage` (`parse_mode=HTML`, `disable_web_page_preview=true`), sharing the same bot token with OpenClaw; fallback `openclaw message send --channel telegram --target <id>` (only if the Next Step 1 test confirms it passes HTML parse_mode). Each successful chunk becomes `sent:true` in `pending-digest.json`. After all chunks are sent, `seen.json` (cluster fingerprints + seenUrls) and `last-run.json` are written and `pending-digest.json` deleted (never before delivery). Uncaught error at any stage: the CLI's catch-all sends "❌ Briefing could not be produced: <short reason>" via the Bot API, writes the status line to stderr only (no duplicate error message) and exits ≠0 → OpenClaw failure alert (after 2 consecutive failures) as extra safety.

**Env variables:** `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_FALLBACK_BASE_URL?`, `LLM_FALLBACK_MODEL?`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `CONTACT_EMAIL` (for the SEC/BLS bot UA), `TZ=Europe/Berlin`. `.env` outside git, 0600.

**Fetcher structure:** the `json-api` fetcher works with a per-source path mapping in `sources.yaml` (`items`, `title`, `url`, `date` JSONPath + optional regex), so ~15 JSON shapes are config. Real bespoke adapters: Coinbase products diff, EDGAR full-text, `t.me/s` HTML, SlowMist HTML, BLS iCal (5).

**stdout contract:** the CLI writes a single status line to stdout ("✅ Briefing sent, 9 items, 2 chunks" / "❌ error: …"); all logs go to stderr and `logs/`. Thus `--announce` relays only the status line regardless of OpenClaw's behavior (last line or full stdout); content goes via `message send`.

### digest.json schema (summary)

```ts
type Digest = {
  generatedAt: string; windowFrom: string; windowTo: string; tz: "Europe/Berlin";
  context: { btcUsd, btcChg24h, ethUsd, ethChg24h, fearGreed, btcEtfNetFlowUsd?, btcEtfFlowDate?, stableSupplyDelta7dPct? /* computed from daily snapshots in state/stablecoin-supply.json (≥8 days) */ };
  calendar: { at: string; tz: string; title: string; kind: "macro"|"unlock"|"fork"|"etf"; asset?: string; url?: string }[];
  items: { id: string; label: "verified"|"news_multi"|"news_single"|"opinion"; score: number; title: string; text: string;
           assets: string[]; entities: string[]; publishedAt: string;
           sources: { sourceId: string; name: string; tier: 0|1|2; url: string; publishedAt: string }[];
           update?: boolean }[];
  sourceErrors: { sourceId: string; error: string }[];
};
```
